# Polygon motion and upload recovery contract

An ordinary image/video layer may retain a percentage polygon with 3–64 points. Each point exposes `maskPoint{0..63}X` and `Y` on the existing motion key/curve store. The actual number of supported channels follows its polygon. Coordinates are bounded to −100..200%; times and values must be finite. Existing point order must be retained across poses. Bypassing a mask keeps its keys; switching to an incompatible shape/topology is rejected before mutation. Enter/blur commits a native numeric value; Escape, seek or track locking cancels an incomplete draft. Custom curves remain the existing Bezier controls. No second animation database exists.

The ordinary layer mask is evaluated on the programme clock in decoded preview, paused preview, track-matte projection and CPU rendering. Legacy static/absent masks retain their defaults. Projected-media restrictions remain explicit. General segmentation, automatic roto, projected masks/groups and unrestricted freeform expressions are not supplied by numeric polygon animation.

Successful asset materialization replaces only the access/source binding when its layer ID, prior source and file identity still agree. Concurrent position/copy edits survive; replacement files cannot be overwritten by a late completion. Each completed upload is retained independently of the rest of the batch. A first failure does not enable Retry until all sibling requests settle. A backend HTTP 429 is retried only with a finite positive declared cooldown at most 60 seconds, within a 120-second per-request wait ceiling. Other errors are returned. No inference/render job is automatically retried.

The local CPU transport keeps its default 512 KiB request limit. An explicit demo-only configuration may select 512 KiB–4 MiB; this operation uses 2 MiB. Signatures, source ownership, request digest, worker admission, artifact caps and financial policy remain unchanged. A larger JSON body is not permission to run a second job.

New raw uploads use an owner-scoped UUID object path. Earlier single-filename image/audio objects remain readable only through the shared ownership/type/size/expiry resolver; video-only consumers reject them. Large generated FFmpeg filters use exact UTF-8 private script files and the same canonical asynchronous subprocess. Files are removed on success, failure, timeout or cancellation; no shell or substitute compositor is introduced.
