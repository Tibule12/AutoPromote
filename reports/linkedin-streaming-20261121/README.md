# LinkedIn upload memory correction — 21 November 2026

A real 50,337,351-byte festival video repeatedly coincided with Render's 512MB instance OOM events. The existing LinkedIn implementation downloaded the entire video into a Buffer before uploading it, adding a video-sized allocation and possible transport copies to an already-running API process. This change streams known-length sources with backpressure. Unknown-length sources stage to a temporary disk file, send its exact length and remove it after success/failure. A deadline aborts stalled transfer and closes the streams. Source and upload destinations retain SSRF validation; upload credentials stay restricted to LinkedIn hosts.

The asset polling path also used a full digitalmediaAsset URN where LinkedIn expects the opaque asset ID. Actual provider reads returned400 with the URN and200/AVAILABLE with the ID. The correction changes the URL path while preserving the media URN in the published post.

Validation: eight focused Jest cases pass. A128MiB generated slow-consumer transfer proves bounded producer backlog, exact size and no full-body read. Unknown-length staging, file cleanup, source destruction on failure, normal video posting/asset-ID polling, existing caption and token-refresh cases pass. Separately, a local connected-account stream uploaded the real50MB file using under100MiB peak processRSS, obtained AVAILABLE and published with providerHTTP201. This local recovery is evidence for the approach; it does not qualify the serving backend's512MB baseline or concurrent upload load. The owner-approved post is https://www.linkedin.com/feed/update/urn:li:ugcPost:7529815857808461824 . Its interrupted task was cancelled before one direct provider request and reconciled with the actual receipt, preventing automatic retries.

The fix has not yet been deployed. Same-job restart recovery, durable asset stages, image buffering and overall backend memory/concurrency limits remain separate work. No plan/memory tier is upgraded by this change. No secret, provider token or signed media URL is committed.
