# Existing Studio subject preview/export bridge

The original private model proof is real, but calling the whole requested integration finished was premature. Its normal Studio subject-preview/export bridge was missing. This follow-up implements that bridge without changing the editor layout, deploying an application/rules/image or starting a GPU.

The existing subject-effects panel now forwards its generic saved mask reference through its existing authenticated preview endpoint. The founder/admin boundary is retained. The backend resolves the immutable mask, owned canonical project/source membership, source hash/generation, source clock, unchanged segmentation prompt and exact output file generations. Effect parameters may change; changing subject points requires a new mask and cannot silently fall back to inference.

A separate CPU mode in the existing VFX worker protocol reads those verified model outputs, bounds archive expansion and file downloads, validates every cached matte against the source and clock, and invokes the existing `render_vfx`. It never probes a GPU or imports a model. Preview jobs retain parent-mask provenance and publish an immutable composite manifest. Review, saved job identity, preview invalidation and final export retain the existing contracts. The normal export resolver now accepts those completed owned CPU jobs, revalidating their mask/source dependencies. Legacy NVIDIA behavior is preserved.

Staged security rules seal subject job/request/capacity collections and `temp_studio_vfx` objects against browser clients, including admins. Server SDK and signed owner-scoped API access remain authoritative. The rules were tested locally and were not deployed.

- [Actual preview](proof/subject-bridge/preview.mp4) and [inspected preview frame](proof/subject-bridge/preview-frame.png): `ON AIR` is occluded by the visible subject and the callout points to that subject. No CSS effect is presented as segmentation.
- [40 CPU runtime/ownership/input guards](subject-bridge-checks/node.txt), [26 subject service and existing component checks](subject-bridge-checks/subject-jest.txt), [24 canonical/Director/intelligence checks](subject-bridge-checks/canonical-jest.txt), [11 worker protocol checks](subject-bridge-checks/worker.txt), and [real emulator client-security checks](subject-bridge-checks/security.txt) pass. Service/component access transports in unit tests are synthetic; they do not qualify a real signed-in lifecycle.

The retained [failure](subject-bridge-checks/review-helper-v1-failure.txt) is corrected to `0.5`; a fresh CPU proof passed and its frame was inspected.

The CPU worker is configured with `STUDIO_VFX_MODE=model_artifact_cpu`, `STUDIO_MODEL_VFX_SECRET`, and a bounded writable job root. The API uses `STUDIO_MODEL_VFX_URL`, the matching secret, and the already default-off model-runtime flag and artifact bucket. `model_workers/Dockerfile.subject-composition` contains FFmpeg/Pillow and this existing renderer protocol; no weights, CUDA or Torch are included. This new image definition has not been built or deployed.
