# Local tutorial production

This pipeline uses the original Byte Lab app as input and the existing AutoPromote Studio as the editor. `capture-practice.cjs` records actual running-program input cases. `narrate.py` uses an offline CPU Piper voice and original explanatory scripts. `produce-lessons.cjs` signs into an already-owned local emulator application and records real editing controls, native save/cold reopen, canonical CPU render and actual native download. `package-lessons.py` muxes explanatory narration onto the interface recording and creates separate plain transcripts and original practice kits, with no caption tracks or sidecars. It never creates an edited target-result movie outside Studio.

Start the existing isolated App with `scripts/monetization/application-demo.cjs` and Java 21, local CPU Python dependencies, explicit finite symbolic test credits and bounded render limits. The first run needs its local `browser-private.json`; it contains test credentials and must never be committed. The proof script must not point to production or a real customer's account. No paid workload or production deployment is part of this pipeline.

Actual UI labels are checked in the running build; do not infer them from hidden legacy fields. Preserve failed takes and receipts. An accepted render that times out must be recovered by its owned job, never resubmitted blindly. The local credit confirmation uses symbolic demo credits; it grants no real-account credit approval.

The source audit is `audit-studio.cjs`. The lesson/page checks and release gates are separate from teaching approval. All published lessons must have complete native, moving-output, parity, reproducibility and teacher-review evidence. Packaging never sets teacher review or independently reproduced learning evidence. The normal public catalog filters out all unreleased lessons. Private local preview uses `REACT_APP_EDUCATION_PREVIEW=true`.

Scripts intentionally keep browser profiles, credentials, full owned project backups, source requests and worker receipts outside the repository. Public practice recipes hold no private owner or Storage paths. The Studio entry creates a fresh project after the current account uploads its own copy of the permitted source.


The foundation now leads into four concept labs referencing the official DBE IT CAPS 2024 Section 3 amendment. `author-bubble-sort.mjs` and `author-concept-scenes.mjs` produce only editable graphics interchange JSON. `produce-bubble-sort.cjs` and `produce-concept-lessons.cjs` import it using actual authenticated Studio controls, change exact keys and render via the normal canonical worker. No browser state, account, worker response or native result is invented. `package-concept-lessons.py` combines actual control recordings, abbreviates unattended render waiting while retaining the complete final playback, and adds disclosed offline narration. It keeps all raw captures and native results intact.

`bubbleSortTrace.mjs` supplies an independent adjacent-pair trace, with duplicate identity and boundary tests. `database-example.sql` is separately executed against fictional rows with foreign keys enforced; Studio is not a SQL engine. `verify-concept-media.py` decodes each native frame and compares paused editor/output pairs. Settled bubble-card positions are tested independently; colour-footprint measurement during white-outline occlusion is diagnostic, not proof of strict pixel parity. Teacher approval and independent student recreation remain false.

Retain both the five-minute local worker failure and its capacity-refused follow-up. `start-bounded-worker.cjs` creates a finite twelve-minute local CPU provider over the same emulator data; production settings do not change. `render-retained-concept.cjs` is only for a saved authored project after the previous worker outcome is verified terminal. It does not authorize duplicate submission of an active/unknown job. Practice JSON creates a fresh owned stage; imported graphics remain a separate normal user action.


`cat/extensions` adds three further genuine HTML/browser sources: heading hierarchy/formatting, readable webpage design and evidence-led path troubleshooting. Its real Studio guides deliberately record in bounded parts at stationary control boundaries, keeping all navigation and actions. Queue/render waits occur off camera. One canonical local export per additional lesson supplies both the standalone movie and finished walkthrough playback. Offline speech is aligned to the actual action clock; the native movie supplies its own sound during final playback. Teacher feedback and independent recreation remain pending.
