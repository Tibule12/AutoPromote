# Technical school demonstration production

This extends the existing Education architecture and actual Studio pipeline.
Only IT, CAT and Technical Education are pathways; the latter contains EGD,
Mechanical Technology, Electrical Technology and Civil Technology. No school
enrolment, minor onboarding, production deployment or paid GPU work is enabled.

The author prepares original **static** SVG geometry and the existing native
`autopromote-graphics` interchange. The source MP4 is an empty 16:9 stage with
disclosed offline synthetic concept narration. **Studio supplies every animated
diagram, key, mask and final teaching film.** Packaging only joins actual control
recordings and aligns their narration; it never renders the concept animation.

The authoritative corrected proof directory is
`~/.local/share/autopromote-qa/education-technical-20261125/revision2`.
The parent directory retains rejected first takes and their original native
movies/projects. Their incorrect practice-label target moved a diagram layer.
Do not reuse those movies. The corrected recorder explicitly chooses the new
text target and refuses export unless every reference layer/key value agrees.

Use a **new** proof directory for a new production attempt. Do not overwrite
completed receipts or resubmit an accepted/unknown job. The scripts accept
`TECHNICAL_EDUCATION_WORK` where applicable. The local runtime is the retained
Auth/Firestore/Storage App at `/tmp/autopromote-application-demo-y1KSZS`.
Its private configuration is not part of the shareable package. Preserve its
wallets/history; no fixture grant, reset or production account change is needed.

The production sequence is:

1. Verify the official DBE PDFs and page references. `author.py` prepares static
   originals, single-layer practice imports, the scaffold and exact reference
   composition. `narrate.py` prepares the empty stage and original voice cues.
   These authoring commands intentionally prepare new material and must not run
   over a completed release's inputs.
2. Run `verify-geometry.py` with the canonical local Python environment. It
   checks the stated third-angle geometry, 361 gear mesh states, 2:1 opposite
   linear rates, the external conventional-current path and the wall's half-module
   stagger. This is bounded technical evidence, not educator approval.
3. Run `record.cjs <lesson-id>` using the normal headless, muted App and local
   canonical CPU worker. Real tool clicks, chooser imports, a manually completed
   key and an original label are captured. Short path labels replace long
   scrolling as the founder requested. Keep the whole workspace/timeline visible.
   The worker lock serialises actual exports; off-camera queue/processing waits
   are excluded from the teaching guide. Keep the 5GiB proof-storage floor.
4. Inspect actual moving previews and native films. Run `verify-movie.py
   <lesson-id>`; it reads all 672 native frames, checks sound and compares the
   retained pre-final canvas samples. For gears it tracks both index markers in
   481 moving frames. Boundary/raster diagnostics do not qualify whole-Studio
   pixel parity. Technical and human creative review are distinct.
5. Run `package.py <lesson-id>`, `print-materials.cjs <lesson-id>`, then
   `finalize.py <lesson-id>`. Each finished package includes its real film,
   narrated actual-control tutorial, original assets, editable native graphics,
   exact recipe, concept/editing exercises, reasoning, review checklist and PDFs.
   After all four complete, the finisher creates one offline review page and ZIP.
6. Run `verify-kit-recreation.cjs`. It uses only the stage and completed graphics
   in a fresh browser through normal sign-in/import/save/cold-reopen, with zero
   renders. The same isolated adult fixture is used: this does not qualify
   cross-account project sharing, an independent learner or school hardware.
7. Verify all page links, players, downloads, local review notes and mobile
   layout, the public media-exclusion gate, and the unchanged IT/CAT bytes.
   Run the Studio contract validator and update the readiness evidence.

Actual owner backups are retained separately in Videos under **Owner projects -
private local access only**. They require their owner's media permission. The
shareable kits contain source plus native graphics so another authorised user
can create an owned copy through the normal workflow. They do not transfer
private Storage capabilities or account credentials.

The local presentation uses the existing `scripts/education/preview.cjs` and
shared Education components. A normal public build removes `technical-v1` and
exposes only its preparation notice. Deployment/public presentation needs the
founder's separate approval, as required by the expansion brief. All original
IT/CAT work and the commercial platform remain preserved. Teacher feedback,
independent learner recreation, actual school-device trials and formal curriculum
approval must never be inferred from successful exports or automated checks.
