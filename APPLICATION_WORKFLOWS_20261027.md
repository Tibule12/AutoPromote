## Reproduce locally

Use installed Node/frontend dependencies, Java 21+, cached Firebase emulator jars and the existing CPU Python environment. This owns fresh ephemeral emulators and a separate `/tmp` build, preserving the user's active build and avoiding Firebase CLI OAuth credentials.

In this worktree, dependencies are shared with the original checkout: set `NODE_PATH` to its absolute `AutoPromote/node_modules` and `AutoPromote/frontend/node_modules` paths, separated by `:`. No dependency installation, remote CI or cloud seed is required.

```sh
CREDITS_JAVA_BIN=/path/to/java21/bin/java \
CREDITS_PYTHON_BIN=/path/to/existing/python \
npm run credits:application-demo
```

The printed private directory contains the demo-only login/origin. Use normal controls or `node scripts/monetization/application-browser.cjs PRIVATE_DIRECTORY PHASE`: `studio-save`, `studio-cancel`, `studio`, `scan`, `publisher`, `queue`, `studio-restart`, `studio-failure`, `studio-zero`, `restore`. Supply a small local `source.mp4` first. Queue uses the guarded `application-demo-fixtures.cjs` precondition after publishing; it writes only the fresh emulator. Zero testing requires preceding real consumption. Export private evidence with `export-demo-evidence.cjs` before stopping. No Google ads are requested.
