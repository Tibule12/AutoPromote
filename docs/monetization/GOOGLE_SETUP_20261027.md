## Manual setup still required

1. **Ad Manager network:** sign in with the intended existing Google/AdSense publisher identity and check whether an Ad Manager network already exists. Create one only if needed, following the linked-account flow. A separate GAM account/network is needed; another AdSense publisher account is not. A valid AdSense account is required even when AdSense serving is not actively used. Confirm reporting currency/timezone before the first order and ask Google if account activation requires assistance. Record the network code separately from the `ca-pub-…` identifier. [Signup](https://support.google.com/admanager/answer/7084151?hl=en).
2. **Demand:** check Admin → Linked accounts and the network's actual entitlement to AdSense/Ad Exchange or suitable reservation demand. A new network/ad unit does not create advertisers or guarantee fill. Ad Exchange availability may require Google or a publishing partner. [Account linking](https://support.google.com/admanager/answer/188529?hl=en).
3. **Site checks:** inspect Inventory → Sites and the approval state applicable to this account/inventory. The documented site-management flow varies by account type; standard owned/operated networks do not have identical mandatory listing requirements to every partner/AdSense flow. Ask Google which approval covers the authenticated tool pages and proposed dedicated credits page. Do not add a real crawler/ad-serving tag as part of this local work. [Site management](https://support.google.com/admanager/answer/10130765?hl=en).
4. **Reward eligibility:** obtain confirmation that nontransferable processing credits are permitted for this site's inventory. Keep them separate from cash, creator payouts, referral money and transferable rewards. Every offer must state the reward/action, require opt-in and permit declining without obstructing ordinary use; never reward clicks or ask users to watch to support the business. [Reward policy](https://support.google.com/admanager/answer/7496282?hl=en).
5. **Completion verification:** obtain the applicable GPT **web** signed callback specification and test fixtures before making a live credit offer. Use the request below. Site approval does not resolve this requirement.
6. **Consent/privacy:** configure Google's required certified CMP where applicable, including EEA/UK/Switzerland requirements. Consent to watch is separate from advertising/storage consent. Review age, regional and privacy requirements and avoid identifying project/user data in targeting. [Certified CMP guidance](https://support.google.com/adsense/answer/13554116?hl=en), [EU consent guidance](https://www.google.com/about/company/user-consent-policy-help/), [PII policy](https://support.google.com/admanager/answer/7686480?hl=en).
7. **ads.txt:** use the exact authorised seller records shown by the approved account/partner and review existing records before publication. Do not infer an exchange seller relationship from the ownership meta tag. [Official ads.txt instructions](https://support.google.com/admanager/answer/9422067?hl=en).
8. **Inventory after separate approval:** create a dedicated rewarded web unit and record its full `/NETWORK_CODE/UNIT_PATH`. Review the web trafficking sizes, eligible demand, reward amount/type and any scoped non-instream-video protection setting. Request only from an approved opt-in page after a compatibility review; do not install Auto Ads or Offerwall over Studio. [Rewarded web setup](https://support.google.com/admanager/answer/9116812?hl=en).
9. **Serving-origin qualification:** test actual CSP/COEP/COOP, CMP, iframe/cookie and blocker behaviour on a named nonproduction origin. Keep the editor's repaired permissions/isolation. A separate local test page's permissive Google CSP is not a production header proposal.
10. **Reporting/payments:** configure dedicated inventory reporting and reconcile estimated versus finalised revenue, invalid-traffic adjustments and actual payout separately from completion receipts and credit issuance. Complete payee/tax/identity/address/payment steps requested by Google. No per-view revenue or payout date is guaranteed. [Payments](https://support.google.com/admanager/answer/2671026?hl=en).

AdSense Offerwall does include rewarded advertising for content-access flows. Its client/custom-choice integration does not by itself establish authenticated account-credit settlement. [Offerwall](https://support.google.com/adsense/answer/13865318?hl=en), [Custom Choice API](https://developers.google.com/funding-choices/offerwall-custom-choice-docs).

No usable GPT web signed contract was verified in the reviewed [GPT release notes](https://developers.google.com/publisher-tag/release-notes). This is an unresolved requirement, not a statement that Google can never offer it.

## Request/display/no-fill lifecycle

The prepared local controller follows the [official GPT sample](https://developers.google.com/publisher-tag/samples/display-rewarded-ad): create a supported rewarded slot, wait for readiness, display after the user's choice, observe browser grant/close and destroy the slot. Video completion or close alone is insufficient even as a UI signal. Some demand is display, so the UI must not promise every ad is a video.

Unsupported slot → no offer; no-fill/blocker/timeout → dismiss/release a pending hold; skip/early close → no reward; already-issued valid server receipt → idempotent settlement according to the eventual reviewed protocol. Never consume the monthly reward allowance for an unfilled request. Keep saved work available and offer retry/subscription information without forcing an ad.

The separate localhost page hardcodes Google's sample unit `/22639388115/rewarded_web_example`. On 27 October it displayed and emitted a client grant; wallet requests and credits were both zero. This tests SDK/lifecycle availability, not AutoPromote approval, account demand, authenticated completion or revenue. No live ad-unit configuration should be substituted into this test script.
